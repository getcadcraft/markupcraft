BCF (BIM Collaboration Format) ဆိုသည်မှာ BIM ကိရိယာများကြား ပြဿနာများ ပေးပို့ရန် ဖွင့်ထားသော ဖိုင်ပုံစံ ဖြစ်သည်။ မော်ဒယ် ညှိနှိုင်းရေးနှင့် ဒီဇိုင်းပရိုဂရမ် အများအပြားသည် `.bcfzip` ဖိုင်ကို ပြဿနာစာရင်းအဖြစ် သွင်းနိုင်သည်။ MarkupCraft သည် **BCF 2.1** ကို ရေးသည်။

## တစ်ခု ပြုလုပ်ရန်

1. {{ui:Markups}} tab ကို ဖွင့်ပါ။
2. ပို့လိုသောအရာများသို့ စာရင်းကို စစ်ထုတ်ပါ၊ ဥပမာ {{ui:Status}} "ဖွင့်ထား"။ စာရင်းတွင် ပါသော မှတ်ချက်များကိုသာ ထုတ်ယူသည်။
3. {{ui:BCF}} ကို ရွေးပါ။
4. မှတ်ချက်တစ်ခုစီ၏ snapshot ရိုက်နေချိန် စောင့်ပါ ("BCF အတွက် snapshot ရိုက်နေသည် (20 ခုမှ 5 ခု)…")။

ရလဒ်: "<name> markups.bcfzip" ဒေါင်းလုဒ်ဆွဲသည်၊ status bar တွင် topic အရေအတွက်နှင့် ဖိုင်အရွယ်အစားကို ပြသသည်။

## အတွင်းပါဝင်သည့်အရာ

မှတ်ချက်တစ်ခုစီသည် **topic** တစ်ခု ဖြစ်လာသည်။

| Topic အကွက် | ဖြည့်ထားသည့်အရာ |
|---|---|
| Title | Punch နံပါတ်၊ အကြောင်းအရာနှင့် စာရွက်၊ ဥပမာ "#4 Cloud on A-101 — Floor plan" |
| Type | မှတ်ချက်အမျိုးအစား (Cloud, Callout, Length…) |
| Status | ဖွင့်ထား၊ လက်ခံထား၊ ပယ်ချထား သို့မဟုတ် ပြီးစီးထား |
| Labels | မှတ်ချက်အမျိုးအစားနှင့် စာရွက် |
| Author and dates | မှတ်ချက်ရေးသူ၊ ဖန်တီးသည့်နှင့် ပြင်ဆင်သည့်ရက်စွဲများ |
| Assigned to, due date | ၎င်း၏ punch item တွင် ရှိလျှင် ထိုမှ ယူသည် |
| Description | စာသား သို့မဟုတ် stamp စာသား၊ တိုင်းတာထားသော တန်ဖိုး၊ မှတ်ချက်၊ စာရွက်နှင့် ဖိုင် |
| Comments | တုံ့ပြန်ချက်တစ်ခုစီ၊ ရေးသူနှင့် ရက်စွဲဖြင့် |
| Snapshot | စာရွက်ပေါ်ရှိ ၎င်း၏နေရာ၏ ပုံ |
| Viewpoint | စာရွက်ပေါ်ရှိ မှတ်ချက်၏နေရာကို အပေါ်မှ ကြည့်သည့်မြင်ကွင်း |

ထိုမှတ်ချက်ကို ထပ်မံထုတ်ယူလျှင် topic ID အတူတူ ရရှိသဖြင့် BCF သွင်းနိုင်သော ကိရိယာသည် တူညီသောပြဿနာအဖြစ် မှတ်မိနိုင်သည်။

## သွင်းသောအခါ ပြန်ဝင်လာသည့်အရာ

{{ui:Import BCF}} သည် BCF 2.0၊ 2.1 နှင့် 3.0 ဖိုင်များကို ဖတ်သည် (buildingSMART 3.0 စမ်းသပ်ဖိုင် 19 ခုဖြင့် စစ်ဆေးထားသည်- topic အားလုံး ဖတ်နိုင်ပြီး စာသားပါသော မှတ်ချက် သုံးခု၏ မှတ်ချက်များ ဖတ်နိုင်သည်)။ သင့်ဖိုင်ဖြစ်သော topic (topic ID အတူတူ) အတွက် မှတ်ချက်အသစ်များကို တုံ့ပြန်ချက်အဖြစ် ထည့်ပြီး status အသစ်ကို ယူသည်။ အခြား topic တိုင်းသည် label သို့မဟုတ် ဖိုင်အမည်တွင် ညွှန်းထားသော စာရွက်ပေါ်တွင် မှတ်စု တစ်ခု ဖြစ်လာသည်၊ မဟုတ်လျှင် ဖွင့်ထားသော စာရွက်ပေါ်တွင် ဖြစ်သည်။ ၎င်း၏ title၊ description၊ တာဝန်ခံနှင့် due date များသည် မှတ်စု၏ စာသား ဖြစ်လာပြီး မှတ်ချက်များသည် တုံ့ပြန်ချက်များ ဖြစ်လာသည်။

| BCF topic တွင် | MarkupCraft တွင် |
|---|---|
| Title၊ description၊ assignee၊ due date | မှတ်စု၏ စာသား |
| စာသားပါသော Comments | တုံ့ပြန်ချက်များ |
| Status Open၊ Accepted၊ Rejected၊ Completed (Closed၊ Resolved၊ Done တို့ကို Completed ဟု ယူသည်) | မှတ်ချက်၏ status |
| Author နှင့် creation date | မှတ်စု၏ ရေးသူနှင့် ရက်စွဲ |
| Camera position | label သို့မဟုတ် ဖိုင်အမည်ဖြင့် စာရွက်နှင့် ချိတ်ထားသော topic အတွက်သာ စာရွက်ပေါ်ရှိ နေရာ |
| Model selection၊ hidden parts၊ clipping planes၊ snapshots | မသိမ်းဆည်း: စာရွက်တွင် ပြရန် မော်ဒယ် မရှိ |

## သိထားရန် ကန့်သတ်ချက်များ

- **စာရွက်သည် မော်ဒယ် မဟုတ်ပါ။** Viewpoint သည် မှတ်ချက်၏ နေရာကို စာရွက်ပေါ်တွင် မီတာဖြင့် တိုင်းထားသည်။ BIM ကိရိယာကို မော်ဒယ်ထဲ နေရာတစ်ခုသို့ မခေါ်ဆောင်နိုင်ပါ။ နေရာကို ရှာရန် snapshot နှင့် စာရွက်အမည်ကို သုံးပါ။
- **Status နှင့် အမျိုးအစားများသည် MarkupCraft ၏ ကိုယ်ပိုင်ဖြစ်သည်** (Open၊ Accepted၊ Rejected၊ Completed၊ Cloud၊ Callout…)။ ဖိုင်က BCF ခွင့်ပြုသလို ၎င်းတို့ကို ကြေညာသော်လည်း ကိုယ်ပိုင်စာရင်း ပုံသေရှိသော ကိရိယာသည် ၎င်းတို့ကို ပြောင်းလဲ သို့မဟုတ် လျစ်လျူရှုနိုင်သည်။
- **သွင်းခြင်းသည် မော်ဒယ် အမြင်မဟုတ်ဘဲ မှတ်ချက်များကို ယူလာသည်။** {{ui:Import BCF}} သည် ထုတ်ယူထားသော မှတ်ချက်များသို့ တုံ့ပြန်ချက်နှင့် status များ ထည့်ပြီး အခြား ပြဿနာများကို မှတ်စုများ ဖန်တီးသည်၊ မော်ဒယ် ကင်မရာကို ပြနိုင်ခြင်း မရှိပါ။ [Markups list and export](topic:markups-list-and-export#import-bcf) ကို ကြည့်ပါ။
- ဒရော်ဝင်း ပြန်လည်သုံးသပ်ရာတွင် မှတ်ချက်များကို PDF အဖြစ် ပြန်ပို့ခြင်းသည် မကြာခဏ ပိုရိုးရှင်းသည်။ BCF သည် ပုံဆွဲမှတ်ချက်များကို မော်ဒယ် ညှိနှိုင်းရေး လုပ်ငန်းစဉ်သို့ ရောက်စေရန်အတွက်ဖြစ်သည်။
