دو لوگ دو نقلوں میں ایک ہی PDF پر مارک اپ کرتے ہیں۔ اگر انہوں نے مختلف مارک اپس کو چھوا ہو، تو نقلیں ہاتھ سے کرنے کے بجائے ایک پروگرام سے ضم ہو سکتی ہیں۔

## یہ کیسے کام کرتا ہے

MarkupCraft جو ہر مارک اپ محفوظ کرتا ہے وہ PDF کے اندر اپنا نام (اس کی آئی ڈی) رکھتا ہے، اور یہ نام کبھی نہیں بدلتا۔ ضم مارک اپس کو اسی نام سے تلاش کرتا ہے، فائل میں ان کی جگہ سے نہیں، کیونکہ ہر پروگرام محفوظ کرتے وقت جگہوں کے نمبر دوبارہ دیتا ہے۔ نوٹس اور سیل شدہ نجی نوٹس بھی اسی طرح ملائے جاتے ہیں۔

شیٹس کو کبھی نہیں چھوا جاتا: دونوں نقلوں میں صفحات کی تعداد ایک ہی ہونی چاہیے۔ اگر وہ مختلف ہوں تو ضم آپ کی نقل کو جیسی ہے ویسی رکھتا ہے اور یہ بتاتا ہے، کیونکہ صفحات شامل یا حذف کرنا کسی انسان کا کام ہے۔

## ترتیب دیں

Git کو ہر ریپوزیٹری کے لیے ایک بار دو لائنیں درکار ہیں:

```
# .gitattributes
*.pdf merge=cadcraft

# ایک بار، ہر کمپیوٹر پر
git config merge.cadcraft.driver "node /path/to/tools/cli/merge.mjs %O %A %B"
```

git کے بغیر `cadcraft merge <base> <ours> <theirs> -o <result>` چلائیں۔ Fossil اور Mercurial اپنی merge-tool ترتیب میں وہی تین فائلیں لیتے ہیں۔ ڈرائنگ کے ساتھ چلنے والی ٹاسک فائل (`<name>.markups.json`، دیکھیں [مارک اپس جو عمل کرتے ہیں](topic:markups-that-act)) اسی طرح، سادہ متن کے طور پر، ضم ہوتی ہے۔

## قواعد

- جو مارک اپ صرف ایک طرف بدلا ہو وہ لیا جاتا ہے۔ دونوں طرف ایک ہی تبدیلی ایک بار لی جاتی ہے۔
- ایک ہی مارک اپ اگر دو طرح بدلا ہو تو یہ **تنازع** ہے: آپ کی طرف برقرار رہتی ہے اور رپورٹ دونوں کو درج کرتی ہے۔ نتیجہ کھولیں اور وہ مارک اپ ہاتھ سے درست کریں۔
- کسی بھی طرف شامل کیا گیا مارک اپ برقرار رہتا ہے۔ ایک طرف سے ہٹایا گیا اور دوسری طرف بغیر چھوئے چھوڑا گیا مارک اپ ہٹ جاتا ہے۔ ایک طرف سے ہٹایا گیا اور دوسری طرف بدلا گیا: ہٹا دیا جاتا ہے، اور رپورٹ ہوتا ہے۔
- لیئرز، کالم، ریکارڈز اور نوٹس انہی قواعد پر چلتے ہیں۔
- سیل شدہ نجی نوٹس کبھی نہیں کھولے جاتے: دونوں طرف کے بلاکس جیسے ہیں ویسے رکھے جاتے ہیں۔

ضم شدہ فائل آپ کی نقل کی مکمل دوبارہ تحریر ہے، جیسے MarkupCraft کا اپنا {{ui:محفوظ کریں}} ہوتا ہے۔ کچھ بھی اپ لوڈ نہیں ہوتا؛ سب کچھ آپ کے کمپیوٹر پر چلتا ہے۔
