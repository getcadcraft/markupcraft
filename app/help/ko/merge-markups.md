두 사람이 같은 PDF를 두 사본으로 마크업합니다. 서로 다른 마크업을 건드렸다면, 사본은 손으로 하지 않고 프로그램으로 병합할 수 있습니다.

## 작동 원리

MarkupCraft가 저장하는 모든 마크업은 PDF 안에 자체 이름(ID)을 지니며, 이 이름은 바뀌지 않습니다. 병합은 파일에서의 위치가 아니라 이 이름으로 마크업을 찾습니다. 프로그램마다 저장할 때 위치 번호를 다시 매기기 때문입니다. 비고와 봉인된 비공개 비고도 같은 방식으로 짝을 짓습니다.

시트는 절대 건드리지 않습니다. 두 사본의 페이지 수가 같아야 합니다. 수가 다르면 병합은 내 사본을 그대로 두고 이를 알려 줍니다. 페이지를 추가하거나 제거하는 일은 사람이 해야 하기 때문입니다.

## 설정

Git은 저장소마다 한 번 두 줄이 필요합니다:

```
# .gitattributes
*.pdf merge=cadcraft

# 한 번, 각 컴퓨터에서
git config merge.cadcraft.driver "node /path/to/tools/cli/merge.mjs %O %A %B"
```

git 없이 쓰려면 다음 명령을 실행합니다: `cadcraft merge <base> <ours> <theirs> -o <result>`. Fossil 및 Mercurial은 각자의 병합 도구 설정에서 같은 세 파일을 받습니다. 도면과 함께 따라오는 작업 파일(`<name>.markups.json`, [마크업을 작업으로 만들기](topic:markups-that-act) 참조)도 일반 텍스트로서 같은 방식으로 병합됩니다.

## 규칙

- 한쪽에서만 바뀐 마크업은 채택됩니다. 양쪽에서 같은 변경은 한 번만 채택됩니다.
- 같은 마크업이 서로 다르게 바뀌면 **충돌**입니다. 내 쪽이 유지되고 보고서에 두 변경이 모두 나열됩니다. 결과를 열고 그 마크업을 직접 고치십시오.
- 어느 쪽에서든 추가된 마크업은 유지됩니다. 한쪽에서 삭제되고 다른 쪽에서 건드리지 않은 마크업은 삭제됩니다. 한쪽에서 삭제되고 다른 쪽에서 바뀐 마크업은 삭제되며 보고됩니다.
- 도면층, 열, 기록, 비고도 같은 규칙을 따릅니다.
- 봉인된 비공개 비고는 절대 열지 않습니다. 양쪽의 블록은 그대로 유지됩니다.

병합된 파일은 MarkupCraft 자체 {{ui:Save}} 기능과 마찬가지로 내 사본을 전부 다시 쓴 것입니다. 아무것도 업로드되지 않으며, 모든 작업은 컴퓨터에서 실행됩니다.
